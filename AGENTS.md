## Project identity and reading order

CacheerPHP is a framework-independent PHP cache library. The Composer package is
`silviooosilva/cacheer-php`; production classes use `Silviooosilva\CacheerPhp\`.
PHP 8.3 is the minimum. Do not introduce syntax requiring a newer PHP version.
The framework must work in vanilla PHP as well as framework applications.

Start with [README.md](README.md), [CONTRIBUTING.md](CONTRIBUTING.md), and
[composer.json](composer.json). For affected behavior, read the implementation and
its tests, then consult [CAPABILITIES.md](CAPABILITIES.md),
[SECURITY.md](SECURITY.md), [MIGRATION.md](MIGRATION.md), and
[WRITING_A_STORE.md](WRITING_A_STORE.md) as needed. Check [CHANGELOG.md](CHANGELOG.md)
before describing a feature as new. Source, configuration, and executable tests

## Architecture rules

1. **Construct and inject cache instances.** Keep the instance-first API. Do not
   restore the v5 global/static operation facade. Named constructors such as
   `Cacheer::file()` and `Cacheer::build()` are factories, not global caches.
2. **Keep the core free of autoload side effects.** The framework must not load
   `.env`, create database schemas, start services, or change the timezone when
   Composer loads it. Inject configuration and connections. Schema migration is
   explicit. `Observability\Telemetry` is an optional process-wide tap, dormant
   without listeners; it is not permission to introduce other global state.
3. **Keep contracts separate.** Application code should depend on `Contracts\Cache`.
   A backend implements `Contracts\Store`: `get`, `set`, `delete`, `clear`.
   Optional behavior belongs to capability interfaces rather than a larger base contract.
4. **Ask about real capabilities.** Use `$cache->supports(...)` or
   `Kernel\Capabilities::supports($store, ...)`. A decorator's `instanceof`
   result alone cannot prove its inner store supports an operation. Explicit
   unsupported operations raise `UnsupportedCapabilityException`; optional
   locking optimizations can fall back to computation.
5. **Preserve composability.** `scope()`/`in()` and `withPolicy()` return a cache
   of the same public type. Scope, policy, and `formatted()` must work together.
   Apply the scope once to keys, tags, and lock names. Prefer scoped cache
   methods over bypassing the cache and manually constructing backend keys.
6. **Keep optional backends optional.** File and Array usage must work without
   Redis, a database server, or optional encryption/compression extensions.
   Do not add a framework dependency to solve an application integration problem.

## Cache semantics that must stay correct

- Distinguish a miss from cached `null`, `false`, `0`, `''`, or `[]`.
  Use `entry()->isHit()` when presence matters; truthiness is not a cache lookup.
- Native TTLs are positive durations or forever. `Ttl::seconds(0)` and negative
  values are invalid. An omitted/null write TTL uses the bound default policy,
  otherwise forever. Use `forever()` or `Ttl::forever()` to state that intent
  explicitly. Read the PSR adapters separately for their different TTL contracts.
- Expired reads are misses; `touch()` must not revive an expired value. Preserve
  creation times and absolute expiry when promoting entries between stores.
- Negative caching must not lengthen an explicit short TTL or shorten an explicit
  forever lifetime. `flexible()` keeps the caller's freshness/stale windows.
- Match scope, tag, and backend prefix names literally. SQL wildcard characters,
  case/accent collation, and Redis glob characters must not broaden invalidation.
  `clear()` affects only the configured keyspace; scoped clearing stays scoped.
- Preserve native batch behavior and transactions through decorators. Wrapping
  a store must not turn one atomic database batch into separate partial writes.
- Tags attach to existing entries. Deletion or clearing ends membership; an old
  tag must never remove a newly created, untagged value under the same key.
- ArrayStore is process-local. Do not describe its counters, cache contents, or
  locks as shared between PHP workers. File locks use process-held `flock`;
  their written TTL does not expire a live handle. Other lock types have their
  own lease semantics. Release only the lock owner's token/handle.
- Atomic operations reject non-integer counters and overflow without altering
  the value. A lock timeout must not silently run an operation unprotected.

## Refresh, tiering, and resilience

- `remember()` coordinates misses when locking is actually available. Preserve
  the read after waiting for another worker and cleanup on exceptions.
- `flexible()` measures age from creation: serve fresh within `fresh`, allow
  eligible stale data up to `stale`, and recompute beyond it. Never serve an
  older value merely because its stored TTL is longer. Deduplicate pending
  refreshes when locking is available, recheck freshness, and release leases.
- **The default executor is synchronous.** Do not promise background refresh
  unless a deferred executor is configured and the runtime can actually send
  the response first. Follow `DeferredExecutor` and the existing executor examples.
- L2 is the tiered store's source of truth. Write L2 before L1. Preserve shared
  generation coherence for bulk invalidation and the L1 age cap: 60 seconds by
  default. A remote single-key change is bounded by that cap, not instantly coherent.
- Only backend outages trigger circuit-breaker fallback. Invalid arguments,
  corrupt data, and programming errors must remain visible. The primary write
  result is authoritative; fallback mirroring is best effort.
- Resilient counters, compare-and-swap, and locks use the primary and fail closed
  during outages. Preserve recovery invalidation so deleted/changed values do
  not return when the primary becomes available again.

## Storage and security

- Preserve the versioned envelope pipeline: serialization, optional gzip, optional
  authenticated AES-256-GCM encryption. Authenticate before accepting decrypted data.
- Reject unknown, truncated, oversized, and unauthenticated payloads with typed
  exceptions. An encrypting pipeline rejects plaintext envelopes. Apply size
  limits to plain, compressed, and encrypted reads before unserialization.
- Keep key rotation able to read entries written with retained old keys.
  Never hardcode encryption keys or print credentials in diagnostics.
- Without encryption, `PhpSerializer` trusts backend data and allows classes by
  default. Use restrictive class handling or encryption for an untrusted/shared
  backend. Redaction in Monitor is not a replacement for storage security.
- v5 payloads are not readable as v6 data. Follow the cold-cache/separate-keyspace
  upgrade path in `MIGRATION.md`; do not restore a permissive legacy reader.
- Telemetry must not change operation results or throw listener errors into the
  application. Preserve safe dispatch, event units, batch forwarding, and optional
  value capture. Cache values must not appear in ordinary logs or metrics.

## Correct usage example

Construct this in the application's composition root and inject `Contracts\Cache`
into services. Keep the cache outside the public web directory.

```php
use Silviooosilva\CacheerPhp\Cacheer;

$cache = Cacheer::build()
    ->file(__DIR__ . '/var/cache')
    ->defaultTtl('5 minutes')
    ->create()
    ->in('catalog');

$product = $cache->remember(
    'product:42',
    300,
    static fn (): array => ['id' => 42, 'name' => 'Example product'],
);
```

For Laravel, bind the configured cache in a service provider and inject it into
application services. For vanilla PHP, construct it in bootstrap/composition
code. Do not hide cache construction, connection settings, or TTL policy in a
controller or template. Verify examples against this branch, not v5 examples.

Use PSR-4 paths, explicit types and visibility, small methods, and the existing
exception hierarchy. Follow `.php-cs-fixer.php`; adopt `strict_types` in untouched

For a code PR, follow `CONTRIBUTING.md`, including store contracts and formatting.
If applying `composer fix`, inspect the resulting diff and keep unrelated files out.

| Affected behavior | Additional relevant checks |
| --- | --- |
| Store or decorator guarantees | `composer test:contract` and the affected conformance tests |
| Envelope, encryption, serialization, limits | `composer test:storage` |

| Worker/process state | `composer test:parallel` |

The default Unit suite already includes kernel, storage, and service-free contract
tests. Use focused checks while iterating; do not keep rerunning equivalent suites
without a new reason. Test real behavior and failure paths, not private implementation.
Use `tests/Support/FakeClock.php` instead of sleeps for cache time tests. Isolate
temporary directories, telemetry state, connections, and keyspaces between tests.

Integration tests may skip absent services locally. CI uses
`CACHEER_REQUIRE_REDIS=1` / `CACHEER_REQUIRE_DATABASE=1` to require them. Never use
a live application's keyspace for tests. Check `.github/workflows/tests.yml` for
the current PHP matrix and service settings. Preserve the ParaTest compatibility
bound in `composer.json` until a changed Pest/ParaTest combination is verified
through fresh resolution and `composer test:parallel`.

For instruction-only or prose changes, verify references, commands, examples,
and `git diff --check`; do not add application tests just to test prose.

## Framework and Monitor integration

Monitor is the separate Composer package `cacheerphp/monitor`, with namespace
`Cacheer\Monitor\`, maintained on `2.x` in the `CacheerPHP/monitor` repository.
Its bootstrap subscribes to v6's telemetry tap. Register listeners before cache
construction; caches already built without instrumentation are not retroactively
wrapped. Avoid duplicate explicit and automatic listeners.

An integration problem may come from the consuming application's dependency
version, event file, environment, pipeline, or process boundaries. Reproduce it
before changing framework contracts. Do not patch installed `vendor/` code as
the final solution. Cross-repo changes require checking both sides and keeping
each repo's diff and verification separate.

The sibling `docs` repo owns documentation sources; `cacheerphp.github.io` owns
the website and published docs build. Do not treat an ignored local `docs/`
directory here as the public documentation source. Update sibling repos only
when the task covers them, and follow their publishing workflow.
